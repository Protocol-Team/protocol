## 🎯 게임 개념 (한 줄 설명)

플레이어가 **해커가 되어 데이터를 탈취**하고, 다음 턴에는 **AI 방어 시스템**이 되어 그 해커의 움직임을 막는 게임입니다.

프로젝트는 처음 `Trace Protocol`이라는 이름으로 기획되었으며, 개발 과정에서 최종적으로 게임명을 `Protocol`로 변경했습니다.

## 🧭 프로젝트 목적

이 프로젝트의 중요한 목표 중 하나는 **개발 경험이 없는 비개발자 팀이 생성형 AI를 활용한 Vibe Coding 방식으로 실제 플레이 가능한 게임을 제작하는 것**이었습니다.

최종 개발을 진행한 3명의 팀원 모두 전문 개발자가 아니며, 코드를 전통적인 방식으로 직접 작성하기보다 자연어로 구현 요구사항을 AI에 전달하고 생성된 결과를 게임에서 테스트한 뒤 수정 방향을 다시 지시하는 반복적인 방식으로 개발했습니다.

`기획 및 요구사항 정의 → AI에 자연어로 구현 지시 → 코드 생성/수정 → 실제 플레이 테스트 → 문제점 확인 → AI에 수정 지시 → 재검증`

게임 기획, 시스템 구현, 디버깅, UI 수정, 밸런스 조정 등 프로젝트 전반에 이 방식을 활용했습니다. 팀원들은 게임 기획, 요구사항 정의, 구현 방향 결정, 플레이 테스트, 문제점 발견, 수정 방향 결정과 결과 검증을 담당했고, AI는 코드 구현 및 수정 과정에 활용했습니다.

## 👥 초기 5인 팀 역할분담

> 아래 역할은 프로젝트 착수 당시 5인 팀을 전제로 나눈 초기 계획입니다. 개발 과정에서 핵심 개발 인원은 3명으로 조정되었습니다.

| 팀원 | 역할 | 담당 영역 |
|------|------|-----------|
| A | 해커 조작 | 이동, 점프, 대시, 에너지 |
| **B** | **리플레이** | **경로 기록, 재생 (핵심 기능)** |
| C | 함정 배치 | 함정 효과, 배치 UI |
| D | 스테이지/보상 | 스테이지 진행, 보상 시스템 |
| E | UI/통합 | 화면 표시, 일일 통합 테스트 |

### 개발 과정에서의 팀 구성 변경

프로젝트는 5인으로 시작했으나 개발 과정에서 지속적으로 핵심 개발에 참여하는 인원은 3명으로 조정되었습니다.

이후 3명의 팀원이 기존에 5개 영역으로 구분했던 업무를 재분배했으며, 참여가 어려워진 팀원의 영역까지 나누어 맡아 개발을 계속했습니다. 최종적으로 3명이 기획, 개발, 테스트 및 AI 활용을 포함한 핵심 제작 과정을 진행했습니다.

## 📅 개발 과정

**개발 기간: 2026.06.25 ~ 2026.08.10**

Protocol은 비개발자 팀이 생성형 AI 기반 Vibe Coding을 활용해 실제 플레이 가능한 게임 제작에 도전한 팀 프로젝트입니다.

### 1단계 — 집중 개발

**초기 약 2주**

- 핵심 게임 구조 및 주요 시스템 구현
- 최초 플레이 가능한 빌드 제작
- Web 버전과 Android 모바일 패키징 구현 및 실행 검증

### 2단계 — 플레이 리뷰 및 보완

**이후 약 2주**

- 실제 플레이 및 외부 피드백을 기반으로 보완
- 게임 시스템, 조작감, 난이도 및 UI 개선
- 이 시점부터 웹 버전의 완성도 향상에 집중
- 이후 모바일 패키징 추가 개발 및 수정 중단

### 3단계 — 추가 개발 및 최종 보완

**이후 ~ 2026.08.10**

- 웹 버전을 중심으로 추가 개발
- 버그 수정, 시스템 보완, 에셋 개선 및 플레이 경험 개선
- 최종 개발 버전을 Web (GitHub Pages) 빌드로 확정

### 플랫폼 개발 이력

> **초기 플랫폼 계획:** Web + Android
>
> 초기 개발 단계에서는 웹 기반 게임을 Android 환경에서도 실행할 수 있도록 모바일 패키징을 구현하고 실제 실행을 검증했습니다. 이 작업은 플레이 리뷰 및 보완 시점까지 진행했으며, 이후에는 웹 버전 구축과 완성도 향상에 집중하기로 개발 방향을 정리했습니다. 따라서 모바일 패키징은 이후 수정하거나 업데이트하지 않았습니다.
>
> **현재 공개 플랫폼: Web (GitHub Pages)**
>
> 현재 버전은 GitHub Pages에서 실행되는 웹 빌드를 기준으로 하며, 초기 개발 단계에서 제작한 모바일 패키징은 현재 공개 버전에 포함하지 않습니다.

## 🎮 초기 게임 룰 설계

> 아래 게임 규칙과 조작 방식은 프로젝트 착수 당시 설계한 초기 기준입니다. 실제 개발 과정에서 플레이 테스트와 기능 조정을 통해 일부 시스템과 조작 방식이 변경되었습니다.

### 공격 턴 (홀수 스테이지: 1, 3, 5, 7, 9, 11)

**플레이어 역할:** 해커

**목표:** 데이터 코어까지 도달해 탈취

**초기 조작안:**

- `A` / `D`: 이동
- `Space`: 점프
- `Shift`: 대시 (에너지 소모)
- `E`: 방어막 (에너지 소모)

**초기 보상안:** 공격 성공 시 보상 3개 중 1개 선택 후 다음 수비 턴에 적용

### 수비 턴 (짝수 스테이지: 2, 4, 6, 8, 10)

**플레이어 역할:** AI 방어 시스템

**목표:** 이전 해커의 움직임을 분석해 함정 배치로 저지

**초기 진행안:**

1. 함정 선택 (레이저, 감전, 카메라, 방화벽)
2. 맵의 슬롯을 클릭해 배치
3. 리플레이 시작
4. 함정 작동 여부 확인

**초기 보상안:** 수비 성공 시 보상 3개 중 1개 선택 후 다음 공격 턴에 적용
